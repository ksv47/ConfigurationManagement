# 0.3.7.33

Выпуск исправляет issue #236 «Определение конфигураций всех баз»: при определении сведений о конфигурации через COM-коннектор для баз с раздельной авторизацией Конфигуратора/Предприятия ранее в строку подключения не подставлялись логин/пароль, из-за чего чтение завершалось ошибкой подключения.

## Исправлено

- **Учёт раздельной авторизации Конфигуратора/Предприятия** при определении сведений о конфигурации (диалог «Определить/обновить конфигурации всех баз» и контекстное меню «Обновить информацию о конфигурации»):
  - у баз, где учётные данные заданы раздельно (`EnterpriseAuth` / `ConfiguratorAuth`) при пустой авторизации `Connection`, теперь в строку подключения попадают реальные `Usr`/`Pwd` — ошибки подключения вида `Pwd=***` или строка без `Usr`/`Pwd` устранены;
  - введён единый резолвинг учётных данных по режиму ([`Services/InfobaseAuthResolver.cs`](Configuration%20Management/Services/InfobaseAuthResolver.cs)): «Конфигуратор» берёт `ConfiguratorAuth`, «1С:Предприятие» — `EnterpriseAuth`, иначе авторизацию информационной базы; учитывается `AuthenticationMode` (Credentials / Windows / Prompt);
  - резолвинг применяется и при построении строки COM-подключения ([`Services/OneCComConnector.cs`](Configuration%20Management/Services/OneCComConnector.cs)), и при запуске 1С ([`Services/OneCLauncher.cs`](Configuration%20Management/Services/OneCLauncher.cs), [`Services/OneCLauncher.Linux.cs`](Configuration%20Management/Services/OneCLauncher.Linux.cs)); режим чтения сведений — «Конфигуратор» — передаётся от вызывающего кода (контекстное меню и диалог, обе платформы);
  - маскирование секретов при логировании сохранено: пароль не выводится в журнал, но в саму строку подключения попадает фактический пароль.

Реализовано в общей кодовой базе и проверено обеими сборками — Windows/WPF и Linux/Avalonia (`-p:ForceLinux=true`) — без ошибок.
