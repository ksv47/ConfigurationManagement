# 0.3.7.14

Выпуск сфокусирован на надёжности обновления на **Linux** (issues #225–#231), а также включает три новых PR по Windows-сборке и восстановлению Linux updater log.

## Что нового

### Linux — надёжность обновления

- **Индикатор хода скачивания обновления** — окно без владельца (вне панели задач), показывает прогресс загрузки по байтам принятого файла.
- **Сценарий-помощник обновления пишет журнал** — весь вывод помощника уходит в `update-helper.log` рядом с `errors.log`: цель, размер файла, свободное место, время ожидания процесса, результат копирования/смены прав/переименования и код запуска новой версии. Журнал подрезается при превышении 512 КБ.
- **Устойчивость журнала** — помощник продолжает работу, даже если журнал недоступен; корректно передаётся код перезапуска приложения и фиксируется достижение таймаута ожидания основного процесса.
- **Исправлено «обновление не срабатывало из сборок, собранных на Windows»** (#225) — переводы строк в сценарии приводятся к виду, понятному bash (`\r\n → \n`), иначе выгруженная на Windows рабочая копия (autocrlf) давала CRLF-сценарий, который bash отвергал, и обновление закрывало приложение без замены файла.
- **Восстановлен метод `EnsureUpdaterLogPath`** (PR #233) — после merge-конфликта Linux-цель перестала собираться (CS0103); объявление возвращено.

### Windows

- **Текст редактируемого списка больше не уезжает под нижний край** (#216, PR #232) — в шаблоне `ModernComboBox` полю `PART_EditableTextBox` задан `Style="{x:Null}"` и `HorizontalScrollBarVisibility=Hidden`; текст снова центрирован, высота редактируемых списков совпадает с соседними полями.
- **Компактный режим больше не даёт разную раскладку в зависимости от пути** (#214, PR #234) — устранены четыре источника расхождения раскладки (масштабирование привязок, захват метрик, обход строки, возврат в обычный режим); раскладка стабильна при старте, переключении тумблера и поиске.
