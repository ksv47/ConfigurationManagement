# 0.3.7.27

Выпуск исправляет issue #175 «Имя КОМ»: шаблон имени COM-коннектора 1С разворачивался неверно, а из диалога правки свойств базы версия базы вообще не учитывалась при чтении свойств конфигурации.

## Исправлено

- **Разворот шаблона имени COM-коннектора без учёта разрядности** ([#175](https://github.com/sivatorov/ConfigurationManagement/issues/175)):
  - версия платформы нормализуется перед разворотом: суффикс разрядности (« (64)»/« (32)») отбрасывается, поэтому «8.5.4.1683 (64)» даёт `V85.COMConnector_1683`, а не ошибочный `V85.COMConnector_168364`;
  - нормализация сделана в единой точке [`Services/ComConnectorTemplate.cs`](Configuration%20Management/Services/ComConnectorTemplate.cs), благодаря чему предпросмотр в настройках и реальное подключение совпадают.
- **Учёт версии базы при вызове «Определить» из диалога свойств базы** ([#175](https://github.com/sivatorov/ConfigurationManagement/issues/175)):
  - раньше `BuildProbeInfobase` в [`ViewModels/ConnectionSettingsViewModel.cs`](Configuration%20Management/ViewModels/ConnectionSettingsViewModel.cs) создавал зондирующую базу без версии платформы, и шаблон разворачивался по максимальной установленной версии вместо указанной для базы;
  - теперь зондирующая база получает `PlatformVersion` из диалога, как это происходит в контекстном меню, поэтому указанная версия базы (например «8.3.27») доходит до разворота шаблона.

Реализовано в общей кодовой базе и проверено обеими сборками — Windows/WPF и Linux/Avalonia (`-p:ForceLinux=true`) — без ошибок.

## Готовность к релизу (сборка 0.3.7.27)

Версия `0.3.7.27` подтверждена во всех четырёх полях `Configuration Management/Configuration Management.csproj` (Version, AssemblyVersion, FileVersion, InformationalVersion).
