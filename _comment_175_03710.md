Доработано в версии **0.3.7.10** — диагностика неуспешного подключения через кастомный шаблон стала полезной:

- В журнал при неудаче теперь пишутся **все перебранные ProgID в порядке перебора** и строка подключения, которую пробовали (раньше — почти без деталей).
- Процесс чтения сведений через COM сообщает родителю последний реально использованный ProgID и при отказе.
- Окно свойств базы и диалог прогресса показывают фактическое имя, развёрнутое по вашему шаблону (например `V83.COMConnector_27`), даже если оно не зарегистрировано в системе.

Важный момент: развёрнутое имя вида `V83.COMConnector_27` **не является зарегистрированным ProgID** — платформа 1С регистрирует только стандартные имена (`V83.COMConnector`). Поэтому подключение именно таким ProgID не может успешно установиться, даже если база версии 8.3.27. Шаблон с суффиксом после версии имеет смысл только если вы сами регистрируете кастомный COM-коннектор с таким именем (например, через утилиту КОМ+ для нескольких версий платформы). Подробнее — раздел CHANGELOG [0.3.7.10](https://github.com/sivatorov/ConfigurationManagement/blob/main/CHANGELOG.md#03710---2026-09-10).
