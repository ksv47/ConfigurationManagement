# Тестирование Linux-порта «Управление конфигурациями 1С»

> Исчерпывающий чек-лист для прогона **на Linux-машине** (Этап 8 финального портирования).
> Реальное тестирование на Windows-хосте невозможно (нет Linux SDK и Linux-версии 1С), поэтому
> перечень сценариев рассчитан на ручной прогон на целевых дистрибутивах Linux.
>
> Сопутствующие документы: [`PLAN_LINUX.md`](../PLAN_LINUX.md) (Этап 8) и [`LINUX_PORT.md`](LINUX_PORT.md) (Этапы 0–7).
> Статус кода: **Этапы 0–7 выполнены**, Windows-сборка не сломана (0 ошибок). Требуется проверка на Linux-хосте.

---

## 0. Подготовка тестовой среды

### 0.1. Целевые дистрибутивы и окружение
- [ ] **Ubuntu** 22.04+ / 24.04+ (x64)
- [ ] **Debian** 12+ (x64)
- [ ] **Astra Linux** SE 1.7+ / Смоленск 1.7+ (x64)
- [ ] **ALT Linux** 9/10 (x64) — при наличии (сборка `.deb` пересобирается через `alien`)
- [ ] Установлена **Linux-версия платформы 1С:Предприятие 8.3** (клиент `1cv8`, например в `/opt/1cv8/<версия>/bin/1cv8`)
- [ ] Установлены системные зависимости: **GTK3**, **glib2**, **xdg-utils** (`xdg-open`, `xdg-user-dir`)
- [ ] Для проверки трея на **GNOME Shell** — расширение **AppIndicator** (`ubuntu-appindicator`); для KDE — штатный системный трей
- [ ] Имеется тестовый набор ИБ: файловая (`/F`), клиент-серверная (`/S`), веб (`/WS`) базы; шаблоны конфигураций; тестовые пользователи/пароли

> Реальную сборку и запуск можно выполнять на Linux-машине; на Windows-хосте этот этап лишь готовит чек-лист.

## 1. Сборка

### 1.1. Обычная сборка `dotnet build`
- [ ] `dotnet build "Configuration Management.csproj" -c Debug` (на Linux) завершается без ошибок
- [ ] `dotnet build "Configuration Management.csproj" -c Release` завершается без ошибок
- [ ] Целевой TFM — `net10.0` (не `net10.0-windows`); `OutputType=Exe`
- [ ] Пакеты Avalonia (`Avalonia`, `Avalonia.Desktop`, `Avalonia.Themes.Fluent`, `Avalonia.Fonts.Inter`) восстановлены; `MaterialDesignThemes` и `System.Management` **не** подключаются
- [ ] Нет предупреждений об отсутствующих/устаревших типах Avalonia 11.3

### 1.2. Публикация self-contained single-file
- [ ] `dotnet publish "Configuration Management.csproj" -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true`
- [ ] Результат — один исполняемый файл `ConfigurationManagement` в `publish/linux-x64/`
- [ ] Файл запускается на чистой машине **без установленного .NET Runtime** (self-contained)
- [ ] Иконка трея (`tray_icon_preview.png`) и иконка приложения (`app_icon_preview.png`) доступны из single-file (встроены как EmbeddedResource)
- [ ] Версия в заголовке окна соответствует `InformationalVersion` (0.3.1.1)

### 1.3. Упаковка
#### AppImage
- [ ] `./package/linux/appimage.sh` собирает `ConfigurationManagement-x86_64.AppImage`
- [ ] AppImage запускается (`chmod +x` + запуск)
- [ ] Иконка приложения в AppDir (`usr/share/icons/hicolor/256x256/apps`) отображается
- [ ] `.desktop`-файл внутри AppImage корректен (`Exec`, `Icon`, `StartupWMClass`)

#### .deb
- [ ] `./package/linux/deb/build-deb.sh` собирает `configuration-management_<версия>_amd64.deb`
- [ ] `sudo dpkg -i ...` устанавливает пакет без ошибок зависимостей
- [ ] После установки приложение доступно в меню приложений с иконкой
- [ ] `sudo apt remove configuration-management` корректно удаляет пакет
- [ ] (опц.) Конвертация в `.rpm` через `alien` для ALT/Fedora
