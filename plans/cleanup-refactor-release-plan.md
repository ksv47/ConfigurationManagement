# План: очистка, рефакторинг и релиз «Управление конфигурациями 1С»

**Проект**: C#/.NET 10, WPF (Windows, `net10.0-windows`) + Avalonia 11 (Linux, `net10.0`).
**Текущая версия**: `0.3.6.76` (задана в 4 полях csproj: `Version`, `AssemblyVersion`, `FileVersion`, `InformationalVersion`).
**Remote**: `github.com/sivatorov/ConfigurationManagement`, ветка `main`.

## Принципы выполнения

1. Каждый пункт (см. ниже) выполняется **отдельной задачей** (через `new_task`).
2. После **каждого изменения кода** обязательно поднимается версия `0.3.6.77 → 0.3.6.78 → …` во всех четырёх полях csproj **и** добавляются записи в `CHANGELOG.md` и обновляется бейдж версии в `README.md`.
3. Итоговый релиз использует последнюю (финальную) версию после всех правок.
4. Перед началом выполнения — `git status` и фиксация текущего состояния.

## Выявленные кандидаты на удаление/доработку

- **Артефакты анализа в корне репо** (не закоммичены): `issue_status.txt`,
  `issues.json`, `issues_analysis.txt`, `open_issues.json`, `open_issues_summary.txt`.
  Требуется подтверждение: временный мусор или нужны? Если мусор — удалить и добавить в `.gitignore`.
- **Дубликаты платформенных файлов** (WPF `.xaml.cs` / Avalonia `.Avalonia.cs`):
  контролы `Controls/`, конвертеры `Converters/` (в т.ч. `Converters/Avalonia/`),
  окна `Views/`. Состав для каждой ОС управляется csproj (`Compile Remove/Include`).
  Проверить: есть ли реально мёртвые файлы, которые **не** входят ни в одну сборку.
- **Возможные неиспользуемые конвертеры**: `GroupFullPathConverter.Avalonia.cs`,
  `NullToBoolConverter.Avalonia.cs`, `MultiValueToArrayConverter.Avalonia.cs` и др. —
  проверить наличие привязок/регистрации перед удалением.

### Задача 3 — Сборка исполняемого файла для Windows
- Выполнить `build-windows-single-file.ps1` (self-contained single-file `dist/win-x64/ConfigurationManagement.exe`).
- Убедиться, что в `dist/win-x64/` только один `.exe`.
- Версия не меняется (нет правок кода).

### Задача 4 — Сборка исполняемого файла для Linux
- Кросс-сборка с текущей Windows-машины: `FORCE_LINUX=1 ./build-linux-single-file.sh`
  → `dist/linux-x64/ConfigurationManagement`.
- Убедиться, что в `dist/linux-x64/` только один бинарник.
- При проблемах кросс-сборки Avalonia — задокументировать и собрать через CI
  (`.github/workflows/release.yml`) либо WSL.
- Версия не меняется (нет правок кода).

- Убедиться, что артефакты `dist/` исключены из репозитория (`.gitignore` / `.codeassistantignore`).

  собранные `ConfigurationManagement.exe` (Win) и `ConfigurationManagement` (Linux),
  а также AppImage/.deb при наличии. Описание релиза — из `CHANGELOG.md`.

## Критерии готовности
- Обе платформы собираются без ошибок после каждой задачи.
- Версия согласована в csproj / CHANGELOG / README / теге релиза.
- `dist/` не попадает в git.
- Релиз на GitHub опубликован с артефактами для Windows и Linux.
