## Детализация исправлений

### #216 — Текст в поле размера шрифта (версия 0.3.7.2)
Симптом: в Настройки → Отображение → Шрифт поле «Размер» показывает текст со смещением вниз (не по центру). Предыдущий фикс центрирования не помог.
Затронуто:
- WPF: [`Views/SettingsWindow.xaml:786`](Configuration%20Management/Views/SettingsWindow.xaml:786) `FontSizeComboBox` + стиль `ModernComboBox` — вероятно `ContentPresenter`/часть редактируемого TextBox не центрируется.
- Avalonia: эквивалент в [`Views/SettingsWindow.Avalonia.cs`](Configuration%20Management/Views/SettingsWindow.Avalonia.cs) (поле размера шрифта).
Действие: обеспечить вертикальное центрирование текста внутри редактируемого ComboBox (в т.ч. `VerticalContentAlignment`/шаблон ContentPresenter/часть TextBox) в обеих сборках; проверить скриншот 7OH.

### #214 — Компактный режим (версия 0.3.7.3)
Симптом: после запуска иконки «уезжают влево», двойное переключение тумблера компактности восстанавливает выравнивание. Регрессия после `ApplyRowCompact`.
Затронуто: [`Themes/ThemeManager.cs`](Configuration%20Management/Themes/ThemeManager.cs:286) (`ApplyCompact`/`ApplyCompactElement`, словари `_compactColumn` и т.п.) — нужно, чтобы при первичном применении/загрузке окна компактность применялась согласованно по горизонтали (колонки `ColumnDefinition`, ширина/выравнивание иконок). Обе сборки.
Действие: устранить разовый «прыжок» горизонтального выравнивания без ручного переключения (например, повторное применение компактности после измерения/загрузки окна, корректное хранение исходных ширин колонок). Проверить, что регрессия из #214 (недавний фикс 0.3.6.97) не возвращается.

### #178 — Окно «Очистка кэша 1С» (версия 0.3.7.5)
Опора на последний комментарий ksv47. Основная часть закрыта. Осталось:

- Разнобой «кэш/кеш»: [`Localization/Languages/ru.json:578`](Configuration%20Management/Localization/Languages/ru.json:578) `CacheClean.OrphanCacheTooltip` — «кеша» → «кэша» (унификация как в заголовке).
- Заметки рядом: комментарий у `IsDeletingName` (`OneCCacheCleaner.cs:457-460`) противоречит поведению (каталоги `*.deleting_*` считаются остатками и переименовываются повторно) — привести в соответствие; неиспользуемый параметр `forOrphanScan` у `GetCacheRoots` (`:806`) — удалить либо задействовать.
Действие: внести перечисленные правки; обновить строки локализации `ru.json`/`en.json` при изменении формата отчёта.

### #175 — Имя КОМ / шаблон COM-коннектора (версия 0.3.7.6)
Опора на последние комментарии 7OH (скобки + какой коннектор использован). Ранее (0.3.6.99) добавлен предпросмотр и обрезка сегментов в [`Services/ComConnectorTemplate.cs`](Configuration%20Management/Services/ComConnectorTemplate.cs:46).
- **Скобочные группы**: поддержать `(...)` вокруг сегментов версии. Если значение плейсхолдера пустое (часть версии не указана) — удалять всю группу со скобками; если значение есть — удалять только скобки, оставляя содержимое. Пример из issue: `V%V12%(вася_%V3%)(пупкин_%V4%)` при `8.3.27` → `V83вася_27`.
- **Логирование ProgID**: в [`Services/OneCComConnector.cs`](Configuration%20Management/Services/OneCComConnector.cs) при подключении/определении свойств писать в журнал фактически использованное имя COM-коннектора (ProgID), чтобы было видно, какой из кандидатов применён (см. вопрос 7OH).
- Проверить поведение пустого шаблона в предпросмотре (7OH: показывает «—»; убедиться, что в рантайме используется стандартный список KnownProgIds без ошибок).
Действие: доработать `ComConnectorTemplate` (общий для WPF/Avalonia) + логирование; обновить предпросмотр в настройках обеих сборок.
