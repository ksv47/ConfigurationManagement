## Issue #226 — Linux: Esc закрывает диалог и главное окно (нет комментариев)

**Запрос пользователя:** при нажатии Esc и наличии открытого дополнительного диалога (свойства базы или настройки) закрывается и диалог, и основное окно.

Корень проблемы (из анализа кода): обработчик `OnKeyDown`/превью клавиш в [`MainWindow.Avalonia.cs`](Configuration%20Management/Views/MainWindow.Avalonia.cs:5794) обрабатывает Esc (`_vm.EscapeToTray`) на уровне главного окна и **не отдаёт** клавишу дочернему модальному диалогу. При открытом модальном окне Esc должен обрабатываться только самим диалогом.

Файл: `Views/MainWindow.Avalonia.cs` (обработчик Esc, строка ~5794).

Решение:
1. В обработчике Esc главного окна проверять, что активное/модальное окно — само главное (не дополнительное). Если открыто модальное окно (свойства базы/настройки), не обрабатывать Esc и не уводить в трей — дать диалогу закрыться.
2. Реализация: добавить условие вида `Application.Current?.Windows.All(w => w is not Window { IsModal: true })` либо проверку фокуса (`FocusManager`), чтобы не перехватывать Esc, когда фокус в модальном окне. Аналогично проверить WPF-версию (`MainWindow.xaml.cs`), если там та же логика.
3. Проверить, что при отсутствии диалога Esc по-прежнему уводит окно в трей (поведение `EscapeToTray` сохранено).

**Критерий готовности:** при открытом диалоге Esc закрывает только диалог; без диалога Esc уводит окно в трей; сборка обеих платформ проходит.

## Issue #225 — Linux: реальное автообновление (последний комментарий `7OH`)

**Суть (по последнему комментарию):** пользователь ставил через DEB; программа пишет про обновление, но обновить файлом нельзя. Просит: если файл запущен из цельного single-file — проверить права записи (создать рядом временный файл и удалить) и, если права есть, провести обновление скриптом; если это deb-пакет — предупредить, что будет запрос повышения прав для установки, и при согласии запускать установку.

Текущее состояние: в 0.3.7.10 реализован только диалог с кликабельной ссылкой на релиз для случая, когда файл нельзя заменить без прав. Нужно **добавить реальный путь обновления**.

Файлы: `Services/UpdateService.Avalonia.cs` (#if LINUX), `Services/ManualUpdateWindow.Avalonia.cs`, `Services/GitHubReleaseService.cs`.

Решение:
1. Определить тип установки (single-file в пользовательской папке vs deb в `/usr/bin` vs AppImage).
2. Для single-file: проверить возможность записи — создать и удалить временный файл в каталоге исполняемого файла. Если получилось — выполнить замену исполняемого файла напрямую (списать бинарник из релиза, скачать, заменить).
3. Для deb-пакета (или когда нужны права): показать диалог «Для установки потребуются права администратора» → при согласии запустить обновление через `pkexec`/`sudo` (например `pkexec sh -c '...'` для скачивания .deb и `apt`/`dpkg -i`). Не запрашивать пароль в терминале из GUI без явного согласия.
4. Сохранить существующий диалог с кликабельной ссылкой как fallback.
5. Добавить ключи локализации и обновить `ManualUpdateWindow`.

**Критерий готовности:** single-file обновляется без прав (замена файла); deb-установка запускает установку через sudo/pkexec после подтверждения; сборка Linux проходит.

## Issue #214 — Компактный режим 2 (последний комментарий `7OH`)

**Суть (по последнему комментарию):** «Всё на месте - изменений не замечено» + скриншот. Несмотря на фиксы 0.3.6.96/97, 0.3.7.6, 0.3.7.10, компактный режим продолжает «разъезжаться» по горизонтали при старте, двойном переключении тумблера, при действиях с полем поиска (клик, крестик).

Файлы: `Views/MainWindow.Columns.cs` (`HeaderOffsetColumn`, `QueueHeaderAlign`, `ForgetCompactWidth`), `Themes/ThemeManager.cs`, `Views/MainWindow.Events.cs` (SearchText), `Views/MainWindow.xaml.cs`.

Решение:
1. Воспроизвести все сценарии: старт в компактном режиме; двойное переключение тумблера; клик в поле поиска; клик по крестику поиска. Зафиксировать, при каком именно действии происходит сдвиг иконок влево.
2. Корневая причина (гипотеза): компенсатор `HeaderOffsetColumn` пересчитывается до полной материализации строк виртуализацией WPF, и пересчёт не срабатывает после действий с поиском (изменение/очистка SearchText), т.к. строка дерева пересобирается, а выравнивание не запускается заново.
3. Убедиться, что `QueueHeaderAlign()` вызывается не только при загрузке строк и изменении SearchText, но и после всех путей пересборки дерева (крестик поиска, сворачивание/разворачивание групп, изменение компактности) на приоритете `ApplicationIdle`/после рендера.
4. Проверить, что `HeaderOffsetColumn` исключён из компактизации ширины (`ForgetCompactWidth`) и не масштабируется коэффициентом компактности.
5. Если виртуализация по-прежнему мешает — рассчитать ширину компенсатора не по измерению строк, а отложенно после полного прохода разметки (двухпроходная отложенная проверка).

**Критерий готовности:** во всех четырёх сценариях (старт, двойное переключение тумблера, клик по полю поиска, клик по крестику) горизонтальное выравнивание компактного режима стабильно, иконки не сдвигаются; сборка проходит.

## Issue #175 — Имя КОМ (последний комментарий `7OH`)

**Суть (по последним комментариям):** у пользователя только COM+ (кастомные ProgID вида `V83.COMConnector_27`); нужно, чтобы по шаблону и версии платформы получалось ИМЯ ком-коннектора, с которым и пытаться подключиться в первую очередь. Две проблемы:
1. **Шаблон не работает при определении свойств конфигурации** — «Была надежда на детальный лог, но там пусто», ошибка «COM-коннектор 1С не зарегистрирован», то есть кастомный ProgID не используется (или не логируется) при чтении свойств базы.
2. **Подстановка в шаблон требует доработки**, когда переменные и в начале, и в конце (суффикс после версии): например `V%V12%.COMConnector_%V3%_%V4%` для версии `8.3.27` должно дать `V83.COMConnector_27`, а не ломаться.

Файлы: `Services/ComConnectorTemplate.cs`, `Services/OneCComConnector.cs` (`BuildProgIdCandidates`, `GetProgIds`), `Services/ComReadHost.cs` (передача списка ProgID агенту), логирование.

Решение:
1. Проверить `ComConnectorTemplate`/`BuildProgIdCandidates`: корректно ли разворачивается суффиксный шаблон (`V%V12%.COMConnector_%V3%_%V4%` → `V83.COMConnector_27`), когда переменные в середине и конце. Исправить подстановку, чтобы при неполной версии отсутствующие сегменты удалялись вместе с разделителями.
2. Убедиться, что кастомный список ProgID передаётся агенту **и при чтении свойств конфигурации** (не только при Connect): `ConfigurationInfoService`/`ComReadHost` должны использовать `GetProgIds(ib)`.
3. Доработать логирование: при неуспехе писать **все перебранные ProgID в порядке перебора** и строку подключения; фактический использованный ProgID (`UsedProgId`) должен попадать в лог и в диагностику окна свойств даже при кастомном шаблоне.
4. Проверить, что кастомный ProgID пробуется первым в переборе (перед стандартными), и что сообщение «не зарегистрирован» не возникает преждевременно из-за кэша доступности (кэш `KnownProgIds` должен обходиться при кастомном шаблоне).
5. Пользователю в комментарии — текстовый ответ (не ссылку на локальный файл), объяснение + версия.

**Критерий готовности:** суффиксный шаблон разворачивается корректно; кастомный ProgID используется и логируется при определении свойств конфигурации и при подключении; сборка обеих платформ проходит.
