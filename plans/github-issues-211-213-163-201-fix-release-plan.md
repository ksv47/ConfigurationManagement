## Issue #213 — Сбой при запуске: окно владелец самому себе + ключ локализации вместо текста

**Файлы:** `Services/WpfDialogService.cs`, `App.xaml.cs` (фатальный обработчик), `Localization/LocalizationManager.cs`.

1. **`WpfDialogService.cs:28` и `:38`** — не назначать `Owner`, если главного окна нет или оно совпадает с самим окном:
   ```csharp
   Owner = Application.Current.MainWindow is { } o && !ReferenceEquals(o, win) ? o : null
   ```
   (для `Confirm` и `Show`). Диалог без владельца показывается нормально, запуск не падает.
2. **Аварийный путь (`App.xaml.cs` фатальный обработчик)** — не полагаться на ещё не загруженную локализацию:
   - считать, что `T` вернул ключ, если результат равен аргументу, и подставлять встроенный русский текст;
   - либо вынести/запускать `LocalizationManager.Instance.Initialize` до всего, что может упасть на раннем старте.
   Выбрать первый (безопасный, минимальный) вариант, задокументировав решение в комментарии к issue.
3. Заголовок и текст сообщения о фатальном сбое должны быть читаемыми при любом состоянии приложения.

## Issue #211 — Недоступные поля паролей при включённом «глазе»

**Файлы:** `Views/ConnectionSettingsWindow.xaml.cs` (WPF) — `ApplyReveal` (~451), `On*PasswordReveal_Click`; связанные XAML-ресурсы `PasswordRevealTextBox`.

Проблема: в WPF при показе пароля используется отдельное `TextBox` только для чтения (`ApplyReveal` прячет `PasswordBox` и показывает read-only поле). Avalonia-версия корректно переключает `PasswordChar`, оставаясь редактируемой.

1. Сделать поле показа (`PasswordRevealTextBox` и аналоги для хранилища и конфигуратора) **редактируемым**.
2. На `TextChanged` поля показа синхронизировать введённое значение обратно в `PasswordBox` и во ViewModel (с учётом `_isSyncingPassword*` и без рекурсии событий), чтобы правка сохранялась.
3. Проверить поведение на всех трёх полях: пароль предприятия, хранилища, конфигуратора.
4. Avalonia-часть дополнительной правки не требует (уже редактируема), но проверить согласованность поведения.
