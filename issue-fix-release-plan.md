## 0. Правила (инварианты для ВСЕХ задач)

1. Перед началом работ — `git status` (чистое дерево) и `git remote -v`, проверка `gh auth status`.
2. Версия живёт **только** в `Configuration Management.csproj` в 4 полях:
   `<Version>`, `<AssemblyVersion>`, `<FileVersion>`, `<InformationalVersion>` (сейчас `0.3.6.79`).
   - `AssemblyInfo.cs` и `VersionInfo.cs` **не трогаем**.
3. После **каждой** правки кода версия поднимается на единицу в последней части
   (`0.3.6.79 → 0.3.6.80 → 0.3.6.81 → …`), и **обязательно**:
   - запись в верх `CHANGELOG.md` (формат Keep a Changelog, `## [0.3.6.8X] — <дата>`);
   - бейдж версии в `README.md` (строка 3);
   - заметка `_release/<версия>.md`.
4. Комментарий в сам issue (`gh issue comment <n>`) с формулировкой «Исправлено в <версия>: …».
   Issue закрывается, если правка решает проблему.
5. Обе платформы обязаны собираться после каждой правки:
   - Windows: `dotnet build "Configuration Management/Configuration Management.csproj"`
   - Linux: `dotnet build "Configuration Management/Configuration Management.csproj" -p:ForceLinux=true`
6. Итоговый релиз использует **финальную** версию после всех правок.
7. `dist/`, `publish/`, временные артефакты анализа — вне git (`.gitignore` / `.codeassistantignore`).

## 2. Группировка и суть правок

### Группа A — Очистка кэша 1С (#178, #195, #202, #198, #196)
Общая область: `OneCCacheCleaner`, окно `CacheCleanWindow` (WPF + Avalonia).

- **#178** (база): переписать поиск каталогов кэша. Платформа хранит GUID каталога в
  `1cv8u.pfl` (корень пользовательского кэша, секция `IdConnStrMap`) как пару
  «строка соединения → GUID». Сейчас ищется по `Infobase.Id`/`GetCacheName` — не совпадает.
  - Читать `1cv8u.pfl` (`%APPDATA%\1C\1cv8` Win, `~/.1cv8/1C/1cv8` Linux), строить карту;
  - у одной базы может быть несколько записей (хост без порта / с портом / IP);
  - `BuildProtectedNames` должен защищать каталоги **живых** баз, иначе они попадают
    в «остатки от удалённых баз»;
  - учитывать второй каталог клиент-серверной базы на Linux (`Srvr__…__Ref__…__`).
- **#195/#202** (падение/ошибка при открытии окна очистки) — проверить код пути открытия
  окна, вероятно связано с рефакторингом #178; устранить исключение.
- **#198**: при открытии окна для конкретной базы — прокрутить список к отмеченной базе.
- **#196**: разрешить вызов очистки при выделении папки (без предустановленных галок).

### Группа B — Импорт из StartManager (#163) и синхронизация групп (#165)
- **#163**: по диагнозу ksv47 в `Services/StartManagerImporter.cs`:
  - имя секции `v8config.smc` = GUID базы = `ID` в `ibases.v8i` → подключение/имя/группа
    берутся из `ibases.v8i`, надстройки (логины/пароли/хранилище/версия) из StartManager;
  - секции без пары в списке баз пропускаются (следы удалённых баз);
  - `settings.cnf` читать как **XML** (`V81AppFile…V84AppFile`), а не как ini-построчно;
  - чтение файлов с определением кодировки по BOM (1.4 пишет UTF-8);
  - расшифровка пароля: ключ **`SLAVKA240601`** (12 симв.), формула «символ + символ ключа − 48»,
    читать через кодовую страницу 1251 (регистрация провайдера кодировок);
  - пароли с кириллицей не расшифровываются — оставлять пусто, не писать мусор.
- **#165**: дубли вложенных папок всё ещё создаются под Windows. Скачать
  `app-20260908.log` (вложение mrtwister) и проанализировать;
  доработать `Services/IbasesV8iImporter.cs` / `IbasesV8iExporter.cs` (нормализация пути,
  дедупликация по полному пути, переназначение `ParentId`).

## 4. Сборка и релиз

**Windows** (Windows-хост): `cd "Configuration Management" && .\build-windows-single-file.ps1` → `dist/win-x64/ConfigurationManagement.exe` (один `.exe`).
**Linux**: `./build-linux-single-file.sh Release` в каталоге проекта → `dist/linux-x64/ConfigurationManagement`; при кросс-проблемах с Windows — WSL/CI `release.yml`.

**Релиз**:
- `git add` (код, csproj, CHANGELOG, README, `_release/`), осмысленные коммиты с привязкой к № issues;
- `git push origin main`;
- `git tag v<финальная_версия>` → `git push origin v<финальная_версия>`;
- `gh release create v<версия> dist/win-x64/ConfigurationManagement.exe dist/linux-x64/ConfigurationManagement --title "<версия>" --notes "$(cat _release/<версия>.md)"`;
- учесть конфликт с CI `release.yml` (overwrite: true — допустимо).
